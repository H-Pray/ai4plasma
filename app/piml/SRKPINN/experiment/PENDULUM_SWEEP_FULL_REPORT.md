## 1. Executive Summary

- The first coarse sweep cycle is complete.
- The decisive improvement came from the time-discretization choice, not from making the network wider, deeper, or smoother.
- Under the fair comparison protocol with fixed physical horizon `T_eval = 20`, the best overall configuration is:
  - `dt = 0.2`
  - `stages = 3`
  - `method = gauss-legendre`
  - `train_data_size = 512`
  - `sample_mode = uniform`
  - `StageDynamics = 1.0`
  - `InitialOrData = 2.0`
  - `learning_rate = 1e-3`
  - `scheduler = MultiStepLR milestones=[2000,4000], gamma=0.5`
  - `layers = [2, 128, 128, 128, 6]`
  - `activation = Tanh`
- Final best run: `act_T20_lr_1em03_ep_6000_w_128_d_3_tanh`
- Relative to the baseline `baseline_v1`, the final best run reduced rollout final error by `89.6%` at the same physical horizon, even though one-step RMSE became worse.
- The coarse architecture sweep suggests that the current `HamiltonianSRKPINN` backbone is close to saturation under this training setup. Further coarse tuning of width, depth, and activation did not produce a better long-rollout model.

## 3. Problem, Model, and Shared Protocol

### 3.1 Problem Definition

The benchmark system is the nonlinear pendulum:

```math
H(q,p) = \frac{1}{2}p^2 + \omega_0^2(1 - \cos q),
```

with canonical dynamics

```math
\dot q = \nabla_p H(q,p), \qquad \dot p = -\nabla_q H(q,p).
```

Shared system settings:

- `omega0 = 1.0`
- state dimension `state_dim = 2`
- training box:
  - `q in [-pi, pi]`
  - `p in [-2, 2]`

### 3.2 Current SRKPINN Architecture

The current model class is `HamiltonianSRKPINN`, implemented in [model.py](../../../../SRKPINN/model.py). Its backbone is a standard feedforward network `FNN`, wrapped by `HamiltonianSRKNet` in [networks.py](../../../../SRKPINN/networks.py).

The core design is:

- the network predicts only RK stage states
- the step-end state is reconstructed by the hard symplectic RK closure
- there is no free output head for `(q_{n+1}, p_{n+1})`

For an `s`-stage method and pendulum `state_dim = 2`:

- backbone input dimension: `2`
- backbone output dimension: `2 * stages`
- first `stages` scalars correspond to `q`-stage values
- next `stages` scalars correspond to `p`-stage values

The learned stage states are:

```math
(Q_1, P_1), \dots, (Q_s, P_s).
```

The stage residuals enforced in the loss are:

```math
R^Q_i = Q_i - q_n - \Delta t \sum_j a_{ij}\nabla_p H(Q_j, P_j),
```

```math
R^P_i = P_i - p_n + \Delta t \sum_j a_{ij}\nabla_q H(Q_j, P_j).
```

The hard end-step closure is:

```math
q_{n+1} = q_n + \Delta t \sum_i b_i \nabla_p H(Q_i, P_i),
```

```math
p_{n+1} = p_n - \Delta t \sum_i b_i \nabla_q H(Q_i, P_i).
```

### 3.3 Training Targets and Data Construction

Each run trains on one-step supervised pairs

```math
(z_n, z_{n+1}^{ref}).
```

When `train_data` is not pre-supplied:

1. initial states are sampled from `PendulumSystem.sample_initial_states`
2. one-step targets are generated by the reference stepper
3. the pair tensor is frozen for that run

Important details:

- `sample_mode = uniform` creates a phase-space grid and truncates to the requested count
- `sample_mode = random` draws iid uniform samples in the phase-space box
- the reference stepper is `SciPy solve_ivp(method="DOP853")`
- tolerances are `rtol = 1e-10`, `atol = 1e-10`
- the dataset is rebuilt for each run

### 3.4 Loss Terms

The total loss is

```math
\mathcal{L}
= w_{stage} \cdot \mathrm{MSE}(R^{stage})
+ w_{data} \cdot \mathrm{MSE}(R^{data}),
```

where

```math
R^{data} = z_{n+1}^{SRK}(Q,P) - z_{n+1}^{ref}.
```

The active loss components are:

- `StageDynamics`
- `InitialOrData`

The baseline loss weights are:

- `StageDynamics = 1.0`
- `InitialOrData = 2.0`

## 10. What the Sweep Says About Architecture Potential

The current coarse sweep supports the following conclusion:

- Under the current `HamiltonianSRKPINN` design and training recipe, width/depth/activation changes are no longer the main bottleneck.
- Several variants achieved lower one-step RMSE than the final best configuration.
- None of those variants improved the primary long-rollout objective.
- In particular:
  - wider networks improved some energy statistics but not rollout accuracy
  - deeper networks became unstable in rollout
  - smoother activations improved one-step fitting but degraded rollout behavior

That means the working hypothesis "this model architecture has roughly reached its current coarse-tuning ceiling" is consistent with the evidence collected here.

The strongest remaining opportunities are therefore not more coarse single-seed backbone tuning, but:

- multi-seed validation
- several initial states and energy levels
- longer-horizon evaluation on the top `2` to `3` candidates
- structurally different model families, such as the planned generating-function branch

## 11. Methodological Note on the Discarded Fixed-200-Step Cross-`dt` Ranking

The repository still retains the earlier fixed-`200`-step `dt x stages` sweep in [SWEEP_LOG.md](SWEEP_LOG.md). That earlier protocol suggested a different `dt/stages` winner because:

- `dt=0.05` at `200` steps means only `T=10`
- `dt=0.1` at `200` steps means `T=20`
- `dt=0.2` at `200` steps means `T=40`

So it was not a fair cross-`dt` comparison. The corrected fixed-time rerun at `T_eval=20` is the one used for all decisions in this report.
